# HepatoPlan frontend design specification

Build the two-page research and education demo described by FE-01 through FE-13 in the [product requirements](<HepatoPlan Product Requirements.md>). The supplied [HTML design reference](design-references/hepatoplan_interactive_3d_liver_resection_planning_platform.html) is the visual reference, particularly its hero and “3D Resection Planning Workspace” section. The application in this repository owns the anatomy, interactions and numbers. The HTML's procedural anatomy, example readings, named surgical presets, vessel and wireframe switches, safety badges and clearance claims do not represent the prepared cases.

## 1. Public demo data is a release prerequisite (FE-01, FE-08, FE-13)

**Package the prepared public catalogue when deploying the frontend demo.** The preflight stages release `research-2` in `public/cases/` with `case-001`, `case-002` and `case-003`. Both landing-page actions lead to **case-002**. Keep the public index and all its versioned files together in the build output.

1. Stage the complete prepared `releases/research-2/` directory under the demo's `public/cases/releases/`, including `ATTRIBUTION.txt` and every case listed in that release. Each case directory must contain `metadata.json`, `labels.bin`, `liver.stl` and `tumour.stl`. Keep source CT files, selection files and the offline dataset outside the public tree.
2. Publish the matching prepared index as `public/cases/index.json` once its release files are available. Package this tree in the static frontend output. The browser requests `cases/index.json` relative to the deployed app base and resolves release URLs relative to the index. Keep local machine paths out of browser code. Revalidate the index and cache versioned release assets immutably. The [release workflow](backend/README.md#publish-a-complete-case-release) also supports preparing a fresh release.
3. Check the **served frontend build** from a fresh tab. Read the actual public index, confirm it lists `case-002`, open each listed case through the selector, and verify successful metadata, label and mesh loads. On `case-002`, render both meshes, move the plane, and obtain a current worker result. A passing synthetic fixture or a preview served directly from the ignored research directory does not verify the public package.

## 2. Application map and navigation

| Page or view | Entry | Exit and state |
| --- | --- | --- |
| Landing | Initial visit. The headline reads **See Beyond 2D. Plan in 3D**, with the break after “2D.” | **Explore HepatoPlan** opens the workspace directly in Plan on the prepared demo. **Try a CT upload** opens the preview. Hero rotation affects only its camera. |
| Plan | Demo entry, case selection, **Back to planning**, or opening a saved plan | Case selection starts a centred cut. Saving stays in place. Compare preserves the working plane. Opening a snapshot restores its plane and details. |
| Compare | Workspace mode switch or **Compare these plans** after a save | **Back to planning** restores the working cut, including unsaved edits. **Open Plan A/B** explicitly opens that snapshot in Plan. A case switch returns to Plan. |
| Case chooser | Header in either workspace mode, or **Choose another case** after an error | List catalogue IDs, mark the active one. Selecting it closes the chooser without a reload. Selecting a different case invokes the unsaved-change rule below. **Try a CT upload** opens the preview. |
| CT upload preview | Landing or chooser | File selection stays inside the dialog. **Continue with demo case** enters Plan on `case-002`. If that case is already active, reuse its working cut. Cancel restores the landing page or the open chooser. |
| Saved plans | Workspace header in either mode | List snapshots for this case and release in save order, with their names and optional details. **Open** restores a snapshot and goes to Plan. Close returns to the invoking mode. |
| Save plan dialog | Plan results panel or **Save and continue** in an unsaved-change prompt | A successful ordinary save returns to the same plane and camera. A successful save during navigation completes the pending action. Cancelling keeps the working cut. |
| Unsaved-change dialog | A case change, opening a snapshot, or leaving the editing workspace would replace a dirty cut | Offer **Save and switch/open**, **Discard and switch/open**, and **Stay** with destination-specific wording. Apply the same rule to in-app Back when it leaves the workspace. Plan ↔ Compare never requires this prompt. |

Keep the app session alive across in-app navigation. Treat Plan and Compare as views of one active case. Refreshing or closing the tab clears snapshots. Communicate this in the save dialog and saved-plan list. If navigation requests Compare without two eligible snapshots, land in Plan with the eligibility message.

## 3. Layout and visual language (FE-02, FE-08, FE-10)

Use the reference's `#060910` background, `#090E17` work surface, faint 48 px grid, near-white text, slate secondary labels and sky-blue accents. Use Inter for interface text and JetBrains Mono for measurements and signed values. Use the reference's thin translucent borders, 24 px outer frame, 16 px inner panels, 16 px panel gaps, restrained corner brackets and compact pill buttons. White fill identifies a primary action or selected preset. Limit the grid and brackets to imaging surfaces or their backdrop.

**Landing.** Use a slim wordmark header and a centred content area up to 1280 px wide. On desktop, give five of twelve columns to headline, research/education description and the two entry actions. Give seven to the dark, framed hero viewer (about 490 px tall). Show the real liver, tumour and plane with a drag-to-rotate cue. Below the hero, “Compare two cuts on the same liver” shows two case-002 views from the same angle. For this fixed teaching example, use stills and formatted readings captured together from the same prepared release and two actual cuts. Regenerate them when the release changes. A **How measurements work** disclosure explains parenchyma volume, FLR and estimated tumour distance. The live editor opens in the workspace.

**Desktop Plan, 1024 px and up.** Above the frame, show the active case and workspace controls, then the workspace title and three preset pills. Inside the frame use **3 / 6 / 3** columns. Left holds anatomy/display and plane inputs. Centre holds the rotatable model (target height 540 px), legend and camera guidance. Right holds live measurements and Save. Put remaining parenchyma and FLR at the top of the right rail, with a thin proportional FLR bar. Keep the slider, its signed value, the cut and these two results visible together at a typical laptop size.

**Desktop Compare.** Keep the case header and frame. With differences off, place selectors on the left and span the remaining width with the A/B table. With differences on, place the rotatable model in the centre, its four-region legend immediately below it, and the table to the right. Let the table wrap row labels. Hide Plan's editing controls throughout Compare.

**Below 1024 px.** Stack the landing copy, actions and preview. In Plan, order the compact viewport, remaining-volume/FLR strip, plane controls, secondary display controls, then detailed measurements and Save. Keep the viewport and strip visible together while operating the sliders, allowing them to scroll away when reading the details. Size the pinned area against available height so a focused slider remains reachable in landscape. Render the two primary values once per layout. In Compare keep the two named value columns side by side, then place the optional model and legend below the table. Constrain scrolling inside dialogs on small screens.

The following groups define the contents of each surface, the data to bind, and the conditions for rendering it. Static copy, units, colours and layout belong to the presentation layer.

| Landing hero viewport, anatomical labels and orbit cue | Demo meshes and default plane, local camera | Draw labels and enable orbit once anatomy is ready. Limit the hero to rotation. Show a local loading or retry state inside its frame. |
| Landing comparison example and methods disclosure | Release-matched stills and measurements described above, static methods text | Two examples share a camera angle and labels. Methods starts collapsed. |
| Workspace header, case chooser trigger, Plan/Compare controls, saved-plan count and trigger | Active mode, catalogue ID, session list for the ready case | Header remains during loading. Show Compare eligibility inline when fewer than two snapshots exist. Hide old case counts on selection. |
| Case chooser list, active mark, upload action, catalogue status/retry | Validated index, active case ID, catalogue request state | Open on request. On empty catalogue show “No prepared cases available” and **Retry**. If only the demo is absent, show its ID and offer available alternatives explicitly. |
| Upload disclosure, single-file picker, filename, choose-again, continue, cancel | Ephemeral filename from the browser picker, demo ID | Before selection state “This preview opens prepared case case-002. Your scan stays on this device.” After selection display the filename and enable Continue. Picker cancellation preserves the dialog. Discard file selection on exit. | Plan heading, working-plan name/status, preset buttons | Session baseline name, draft state, `PLANE_PRESETS`, current geometry | Start with “Working cut”. Show the saved name after save/open and “Unsaved changes” after an edit. Show an active preset only when its angle and offset match the current geometry. Disable editing until case ready. |
| Display controls and model legend | Viewer-local plane visibility and liver opacity, viewer colour constants | Show Plane starts on and liver opacity starts at 55%. Label removed tissue (copper), remaining tissue (teal), tumour (rose) and plane (pale blue). Changing opacity or hiding the plane preserves the selected cut and results. |
| Plane inputs, signed readouts, removal side, flip and reset | `planeReadouts`, liver bounds, plane normal/point and removal-side state | Offset is a whole mm along physical X with case-specific limits. Angle is a whole degree around physical Z, −45° to +45°. Label the selected positive/negative side of the plane. **Flip removal side** changes that side. **Reset plane** restores centred 0 mm, 0° and positive side. Presets set both readouts together and preserve the side. |
| Plan viewport, camera guidance, case status and retry | Three.js scene and OrbitControls, controller case state | Support orbit, pan and zoom. Camera gestures redraw locally. | Volumetric analysis, FLR bar, intersection, distance, updating/error status, Save | Current `measurementPanel(state)` and its result | Ready shows the values defined below. During calculation keep labels, clear values and bar, announce “Updating measurements…”, and disable Save. On failure offer **Retry measurements**. Other plane edits remain possible. |
| Save form, name, procedure type, reason, notes, session notice, save/cancel | Local form draft, optional details of an opened snapshot, current ready result | Name is required after trimming. | Saved-plan list, details, open action, empty state | `PlanSession.list()`, scoped by release and case | Zero plans shows “Save a cut to revisit it here.” Use plan IDs as keys. Distinguish duplicate names in selectors with their save-order numbers. |
| Unsaved-change prompt and pending action | UI's saved/default baseline, working plane and requested destination | Mark dirty when plane geometry or removal side differs from baseline. | Compare controls, A/B plan selectors, Swap A/B, Open A/B, Back to planning, Show differences | Distinct saved IDs from current case and release, current pair, local mode/toggle | At zero plans explain that two are needed. | Compare table with plan-name headers and six measurement rows | `PlanSession.compare([aId, bId])` from immutable saved results | Visible immediately for a valid pair, including while differences load or fail. Update headers and values together whenever a selector changes. |
| Difference viewport, four labelled swatches with mL values, updating/error and retry | Active pair's saved planes, viewer comparison mode, controller comparison result and `differenceRegions` | Toggle starts off. ## 5. Data ownership and update sequence

1. **Load catalogue and case.** Use [the existing loader](frontend/src/planning/case-loader.ts) to fetch and validate the public index with revalidation. Maintain one [case controller](frontend/src/planning/case-controller.ts) and one [plan session](frontend/src/planning/plan-session.ts) for the app session. Reuse a ready or in-flight demo selection when moving directly from hero to Plan. The controller verifies the case is listed, fetches metadata, checks case/release identity, then loads both STL files and the label buffer in parallel. Metadata supplies dimensions, voxel spacing and voxel-to-world transform. The loader checks label-buffer length. Decoded meshes feed the viewer. The label buffer transfers to the worker once per case load.
2. **Render and edit.** Mount the repository's [Three.js viewer](frontend/src/planning/resection-viewer.ts) into a sized container. Expose hero-only orbit restrictions in the viewer adapter. Build UI inputs around [plane controls](frontend/src/planning/plane-controls.ts). The controller publishes the changed plane immediately and schedules the latest evaluation. The viewer clips and colours the surface in case coordinates. The worker measures from labelled voxels. Bind camera and visibility changes to the viewer only. Unsubscribe and dispose obsolete viewers and WebGL resources. Keep the controller/session across mode changes.
3. **Display measurements.** Bind the authoritative fields below using [the measurement formatter](frontend/src/planning/measurements-panel.ts). Each removed/remaining percentage uses total **parenchyma**, excluding tumour. The FLR bar uses the same FLR value as its label. Use locale formatting at display time and preserve full precision in snapshots.

   | Output | Worker result field | Display |
   | --- | --- | --- |
   | Remaining parenchyma and Future Liver Remnant | `remainingMl`, `flrPercent` | mL and % |
   | Total parenchyma | `totalParenchymaMl` | mL, Plan only |
   | Removed parenchyma and resection percentage | `resectedMl`, `resectedPercent` | mL and % |
   | Tumour intersection | `tumourIntersectsPlane` | “Touches or crosses” or “Separate” |
   | Tumour-to-plane distance (geometric estimate) | `tumourPlaneDistanceMm` | mm |

4. **Save and reopen.** The session records ID, release ID, case ID, name, optional details, point in mm, normal, removal side and current result. UI state owns the form, draft baseline, dialogs and pending destination. Reopening uses the saved ID, restores details and invokes a fresh evaluation. Returning from Compare leaves the draft intact. A case switch clears the working baseline and pair, aborts the previous load and starts the new default cut. Returning to a case retrieves its saved list.
5. **Compare.** Read table numbers from snapshots. Pass the selected pair to `PlanSession.selectComparison` when entering Compare or changing A/B. This schedules a worker scan for four disjoint parenchyma regions. **Show differences** changes presentation and uses that pair's calculation. Source both colours and labels from [the difference panel](frontend/src/planning/plan-difference-panel.ts): removed only by A (blue, `removedOnlyByAMl`), only by B (orange, `removedOnlyByBMl`), removed by both (slate, `removedByBothMl`), and retained by both (light grey, `retainedByBothMl`). Exit difference rendering on return to Plan.
6. **Reject stale work and recover.** Render from current controller subscriptions. Measurement results must match selection token and plane revision. Comparison results must match selection token, request ID and ordered plan IDs. The controller handles recovery and superseded jobs. Retry index failures through the loader, case/measurement failures via `controller.retry()`, and difference failures via `retryComparison()`. Keep research and education wording visible during recovery.

## 6. Implementation review and acceptance

- Use shared control, viewer, measurement and dialog components for desktop and mobile. Keep navigation, forms and presentation preferences in the UI. Reuse existing loader, worker, geometry, formatter and session logic. The browser fixture is a wiring example. The production entry must use the repo's installed Three.js and bundle the module worker.
- Match the supplied hero and workstation at desktop width. At 390 px verify the cut, current slider, remaining volume and FLR can be inspected together. At intermediate widths check long plan names and table labels. Ensure no horizontal page scroll, overlapping controls or duplicate visible metrics.
- Provide visible keyboard focus, labelled sliders with signed values and units, keyboard-operable camera actions, text legends with swatches, and proper A/B table headers. Where OrbitControls needs an explicit keyboard action, provide it in the viewer adapter. Dialogs trap focus, close on Escape like Cancel, and restore focus to the opener. Announce meaningful loading or failure states once per operation.
- Exercise both landing paths, file-picker cancel/reselect, missing demo case, empty index, bad asset, and retry. Verify the upload path makes no file-content request and the actual model identity is always visible.
- Exercise the real public case through presets, keyboard slider edits, side flip, reset, hide plane and opacity. Rapidly edit while results update, switch cases mid-load and change pairs mid-comparison. A superseded number or colour must never appear as current.
- Save two variants with details, compare, toggle differences, return to an unsaved cut, cancel and confirm an explicit plan switch, then switch cases and return. Test zero/one-plan eligibility, duplicate names, geometry failure with retry and session reset on refresh. For identical cuts both exclusive volumes must be zero. For distinct cuts use **Swap A/B** and verify the exclusive volumes and highlights exchange identities. The four regions must sum to total parenchyma within display rounding.
